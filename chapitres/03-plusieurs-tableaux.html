3  Perturber plusieurs tableaux

Une diffusion réelle ne comporte jamais un seul tableau. Le chiffre d’affaires est publié par région, par secteur, par croisement des deux — et souvent sur plusieurs millésimes. Deux questions se posent alors : les perturbations restent-elles cohérentes entre publications, et comment traiter les tableaux en série ?

3.1 La même cellule reçoit toujours le même bruit

C’est la propriété centrale, et elle mérite d’être vérifiée plutôt que crue.

Le tirage ne dépend ni du tableau, ni de la valeur de l’agrégat, mais uniquement de la clé de cellule — laquelle ne dépend que de ses contributeurs — du nom de l’indicateur et de l’opération d’agrégation. Deux cellules composées des mêmes entreprises portent donc la même clé, et reçoivent le même bruit, où qu’elles soient publiées.

Notre jeu de démonstration contient un cas taillé pour l’illustrer : la région R12 ne compte qu’un seul secteur, S1. La cellule « région R12 » du premier tableau et la cellule « R12 × S1 » du tableau croisé rassemblent exactement les mêmes entreprises.

pert_region <- pm_perturb(tables$region, "ca", "ca_x1", "ck", params,
                          x2 = "ca_x2", indicator = "chiffre_affaires")

pert_croise <- pm_perturb(tables$region_secteur, "ca", "ca_x1", "ck", params,
                          x2 = "ca_x2", indicator = "chiffre_affaires")

a <- pert_region[pert_region$region == "R12", ]
b <- pert_croise[pert_croise$region == "R12", ]

rbind(
  data.frame(source = "région",  ck = a$ck, ca = a$ca, ca_pert = a$ca_pert),
  data.frame(source = "croisé",  ck = b$ck, ca = b$ca, ca_pert = b$ca_pert)
)
#>   source     ck    ca ca_pert
#> 1 région 0.2097 31318   31253
#> 2 croisé 0.2097 31318   31253

Même clé, même total, même valeur perturbée. Cette cohérence n’est pas un effet secondaire : c’est elle qui ferme l’attaque par moyennage, où un attaquant observant plusieurs versions bruitées d’une même valeur en retrouverait la valeur réelle en les moyennant.

ImportantCe que cette propriété exige de vous

La cohérence tient à la stabilité de trois éléments : les clés individuelles (tirées une fois pour toutes), le nom de l’indicateur et le nom de l’opération. Renommer chiffre_affaires en ca entre deux campagnes change tous les tirages et rouvre l’attaque par moyennage. Ces noms relèvent d’une gouvernance, pas d’une convenance de code.

À l’inverse, deux indicateurs distincts sur les mêmes cellules doivent recevoir des bruits indépendants — et c’est bien le cas, l’effet d’avalanche du hachage SHA-512 rendant les deux tirages sans lien apparent.

autre <- pm_perturb(tables$region, "ca", "ca_x1", "ck", params,
                    indicator = "effectifs")

data.frame(
  ck            = head(pert_region$ck, 4),
  cle_ca        = head(pert_region$ck_nu, 4),
  cle_effectifs = head(autre$ck_nu, 4)
)
#>       ck cle_ca cle_effectifs
#> 1 0.2235 0.4400        0.5767
#> 2 0.7124 0.1496        0.4786
#> 3 0.8598 0.2030        0.6208
#> 4 0.9016 0.6154        0.3949

3.2 Traiter une série de tableaux

En pratique on dispose d’une liste de tableaux partageant le même schéma. Le plus simple est d’écrire une fonction de perturbation propre à la campagne, puis de l’appliquer à toute la liste.

perturber <- function(tab, indicateur = "chiffre_affaires") {
  pm_perturb(
    tab,
    total     = "ca",
    x1        = "ca_x1",
    x2        = "ca_x2",
    ck_var    = "ck",
    params    = params,
    indicator = indicateur
  )
}

tables_pert <- map(tables, perturber)

map_int(tables_pert, nrow)
#>         region        secteur region_secteur 
#>             12              8             89

Le même objet params sert pour tous les tableaux : c’est ce qui garantit qu’une seule politique de confidentialité gouverne l’ensemble de la diffusion.

Les métriques se collectent de la même façon, en empilant les résultats :

bilan_utilite <- imap(
  tables_pert,
  \(x, nom) cbind(tableau = nom, assess_utility_empirical(x))
) |>
  list_rbind()

bilan_utilite[, c("tableau", "n_cells", "mean_abs_dev",
                  "theo_mean_abs", "max_abs_dev")]
#>          tableau n_cells mean_abs_dev theo_mean_abs max_abs_dev
#> 1         region      12        2.219         2.043       6.906
#> 2        secteur       8        1.922         2.475       5.490
#> 3 region_secteur      89        4.116         4.624      47.796
bilan_risque <- imap(

La lecture est instructive : le tableau croisé, plus fin, comporte davantage de cellules fortement dominées, donc une perte moyenne plus élevée — le mécanisme concentre bien le bruit là où le risque se situe.

3.3 Vers une mise en production

Dès que les indicateurs se multiplient, mieux vaut piloter le traitement par une table de configuration plutôt que par du code répété. Chaque ligne y décrit un travail à effectuer : quel tableau, quel indicateur, quelle opération.

plan <- expand.grid(
  tableau    = names(tables),
  indicateur = c("chiffre_affaires", "effectifs"),
  stringsAsFactors = FALSE
)
plan$operation <- "sum"
plan
#>          tableau       indicateur operation
#> 1         region chiffre_affaires       sum
#> 2        secteur chiffre_affaires       sum
#> 3 region_secteur chiffre_affaires       sum
#> 4         region        effectifs       sum
#> 5        secteur        effectifs       sum
#> 6 region_secteur        effectifs       sum
resultats <- pmap(plan, function(tableau, indicateur, operation) {
  pm_perturb(
    tables[[tableau]],
    total = "ca", x1 = "ca_x1", x2 = "ca_x2", ck_var = "ck",
    params = params, indicator = indicateur, operation = operation
  )
})
names(resultats) <- paste(plan$tableau, plan$indicateur, sep = "__")

names(resultats)
#> [1] "region__chiffre_affaires"         "secteur__chiffre_affaires"       
#> [3] "region_secteur__chiffre_affaires" "region__effectifs"               
#> [5] "secteur__effectifs"               "region_secteur__effectifs"

Cette forme apporte trois bénéfices en production. Le plan est auditable : on voit d’un coup d’œil ce qui a été traité, et sous quel nom d’indicateur. Il est versionnable : conservé d’une campagne à l’autre, il documente les conventions de nommage dont dépend la cohérence. Et il est parallélisable : pmap() se remplace par furrr::future_pmap() sans autre changement, ce qui compte sur des tableaux volumineux.

3.4 Archiver la trace

Chaque table perturbée emporte sa configuration. Il est prudent de la collecter séparément avant toute manipulation, les verbes dplyr supprimant les attributs.

traces <- imap(resultats, \(x, nom) {
  m <- attr(x, "pm_meta")
  data.frame(
    sortie     = nom,
    indicateur = m$indicator,
    operation  = m$operation,
    sigma_nu   = m$params$mechanism$sigma_nu,
    sigma_eps  = m$params$mechanism$sigma_eps,
    n          = m$params$mechanism$n,
    key_digits = m$key_digits,
    cellules   = m$n_cells,
    non_perturbees = m$n_unperturbed
  )
}) |>
  list_rbind()

head(traces, 3)
#>                             sortie       indicateur operation sigma_nu
#> 1         region__chiffre_affaires chiffre_affaires       sum      0.4
#> 2        secteur__chiffre_affaires chiffre_affaires       sum      0.4
#> 3 region_secteur__chiffre_affaires chiffre_affaires       sum      0.4
#>   sigma_eps n key_digits cellules non_perturbees
#> 1   0.02551 4          9       12              0
#> 2   0.02551 4          9        8              0
#> 3   0.02551 4          9       89              0

Ce petit tableau est la pièce à archiver avec la diffusion : il contient tout ce qu’il faut pour reproduire la perturbation à l’identique, ou pour justifier les choix devant un comité — à condition, bien sûr, que les clés individuelles soient elles aussi conservées.
